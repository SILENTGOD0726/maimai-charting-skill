# maimai-charting Agent Skill · V2.2

**一个帮助AI研究参考谱、理解音乐结构、设计动作并检查谱面的舞萌DX写谱技能。**

安装后，你可以让支持Agent Skills的AI助手协助完成：参考谱研究 → 歌曲与段落规划 → 节奏骨架 → 空间配置 → 检查与修改。适用于新写自制谱、修改已有谱、分析官谱或自制谱，以及排查滑星蹭TAP、撞尾、多押和启动节奏问题。

它是一套供AI读取的方法、模板与轻量检查工具。**不是独立谱面编辑器，也不会单靠安装就让AI达到官方谱师水平。** 音频听辨、编辑器预览与实际试玩取决于你所用AI环境及外部工具。

## 能帮你做什么

| 你要做的事 | 技能会怎样协助 | 通常会得到什么 |
|---|---|---|
| 从音乐开始写谱 | 确认音源与时间坐标，选择主声部，规划段落和动作动机 | 段落表、节奏骨架、simai/maidata草稿 |
| 改善休息段、高潮与发狂段 | 分析持续占手、密度变化、动作幅度和进入/收束 | 段落修改方案与原因 |
| 设计交互、扫键、转圈与复合滑条 | 将技巧组织成短句，检查入口、发展、落点与出口 | 局部方案、候选手顺 |
| 排查蹭TAP、撞尾、多押 | 同时看两手持续任务、滑条启动、沿途区域和下一输入 | 风险时间表、最小修改建议 |
| 研究官谱或优秀自制谱 | 分开研究全曲结构与局部手法，核对来源和时间位置 | 参考谱研究卡、可迁移条件 |
| 检查格式和导入问题 | 快检基本结构，再结合目标解析器/播放器 | 检查结果与未验证项 |
| 根据玩家反馈迭代 | 保留用户认可的音乐动机，优先修关键问题 | 修改前后片段、复核记录 |

### V2.0更关注的三件事

- **音乐取舍**：先决定表现什么声音，再决定省略什么；不是把所有声音都变成独立输入。
- **连续动作**：不只检查某个瞬间或滑条头尾，还检查整个乐句中的占手、换手、路径与接续。
- **可核查的结论**：听审、解析、模拟画面、目标编辑器与真人试玩分别记录，不混称“已验证”。

## V2.1新增：让配置成为完整的动作短句

V2.1重点改进“单个配置能运行，整段却枯燥”的问题：

- **入口到出口一起设计**：检查上一句留下的手位、持续任务、短句发展、最后落点及下一句准备时间。
- **重复与变奏有依据**：保留可识别的节奏或运动关系；镜像不自动等于机械，增加轨迹种类也不自动变得有趣。
- **用整曲安排局部**：把开场、发展、集中展开、恢复和收束作为可选功能，按实际音乐组织；不把试片循环成整曲。
- **核对实际轨迹**：检查弧向、沿途区域、路径长度和连锁出口；不以一句“可以换手”掩盖飞手。
- **保留已认可的版本**：记录用户认可的结构与风格，优先修具体问题；认可不自动等于音押、试玩和定级通过。

可直接这样提问：

> 这段配置很枯燥。请先找音乐选择、动作发展和出口的问题，比较两种有明确表达意图的方案，不要直接加密或增加轨迹种类。不能听审的部分请标明。

> 我认可当前整曲结构与风格。请以这一版为基准，只处理我指出的对轴和蹭键问题，并检查关联的前后手顺。

方法见[完整短句与迭代](references/phrase-and-iteration.md)，复杂乐句可使用[短句规划表](assets/phrase-plan.md)。详细版本记录见[CHANGELOG](CHANGELOG.md)。

## V2.2新增：用案例研究设计，并把可玩性纳入验证

- **具体案例与反例**：以公开资料和用户提供的转写为依据，分析持续占手、节奏细分变化、滑条接续，以及不同难度的比较条件；每例注明可确认范围与推断限制。[阅读案例](references/design-cases.md)。
- **证据分层**：分别记录作者亲述、视频画面、谱面转写、个别玩家反馈和设计推断。只研究了截图片段时，不能说看过全曲；未听音时不能声称确认了采音。
- **相同节奏的动作对照**：保持输入时刻和持续任务，比较出口位置、候选手顺与下一输入时间，帮助发现机械配置或可能的接续问题。
- **关注玩家体验**：从音乐同步、动作流畅、读谱、趣味、挑战、人体动作和重复游玩角度提出可检验的问题；几何距离、模型零警告和模拟图不能证明手感或乐趣。
- **跨谱面比较更可靠**：先核对曲目、版本、难度、时间基准与采样范围，再提出假设；不将不同来源的转写差异直接当作作者设计。

例如可以这样提问：

> 使用 maimai-charting，分析我提供的两段同歌谱面：先对齐版本和时间，再比较音乐依据、连续动作与难度表达；将观察、作者说明、玩家反馈和你的推断分开，提出一组保持节奏不变的动作对照和试玩方案。

本次更新是创作方法、研究卡和行为试用题目；没有新增自动听音、自动判定手感或自动定级功能。

## 安装

### 方式一：使用Git

如果你的AI工具支持项目级 .agents/skills 目录，在自己的项目根目录执行：

~~~bash
git clone https://github.com/SILENTGOD0726/maimai-charting-skill.git .agents/skills/maimai-charting
~~~

个人级安装，可将仓库放到用户目录下的 .agents/skills/maimai-charting。Windows对应：

~~~text
%USERPROFILE%\.agents\skills\maimai-charting\
~~~

对于采用其他技能目录的工具，按照该平台文档选择位置，例如支持Skills的GitHub Copilot可使用项目的 .github/skills/maimai-charting/。

### 方式二：下载ZIP

1. 在本仓库点击 Code → Download ZIP，解压。
2. 将解压目录改名为 maimai-charting。
3. 把整个目录放入你的AI工具所支持的技能目录。
4. 确认 SKILL.md 直接位于 maimai-charting 文件夹内，同时保留 references、assets、scripts 和 tests。
5. 重新载入技能，或在新聊天中明确说“使用 maimai-charting 技能”。

正确的层级示例：

~~~text
你的项目/
└── .agents/
    └── skills/
        └── maimai-charting/
            ├── SKILL.md
            ├── references/
            ├── assets/
            ├── scripts/
            └── tests/
~~~

不要只复制SKILL.md，也不要把仓库再套进一层同名目录。各平台的发现机制、工具权限和目录约定以其文档为准；本项目不自动安装编辑器或播放器。

## 直接这样问AI

### 新写谱面

~~~text
使用 maimai-charting 技能。
我提供了音频，想做一张以旋律和连续滑条为主的MASTER自制谱。
先确认BPM、偏移和段落，给出整曲体验规划，
再写一个有代表性的8—16小节短段供我检查。
无法实际听取或预览的部分请明确标注。
~~~

如果还没提供音频：

~~~text
使用 maimai-charting。先给我一份以主旋律为核心的谱面设计方案，
暂时不写已对轴的整曲，也不要根据曲名猜BPM或声部。
~~~

### 修改已有谱面

~~~text
使用 maimai-charting。检查这份maidata的第16—24小节。
保持取音与原有动作主题，重点修正滑条沿途蹭TAP和尾后接键的问题。
保留原文件，给出最小修改、候选手顺及尚未验证的内容。
~~~

### 学习参考谱

~~~text
使用 maimai-charting，研究这段谱面确认视频的1:08—1:17。
我想学复合滑条如何进入、发展和收束。
请核对时间位置、拆分持续任务，并说明哪些组织方式能迁移到我的歌。
不能从画面确认的语法、声音和真实手法不要猜。
~~~

### 只检查格式

~~~text
使用 maimai-charting，先对这个maidata运行结构快检，
再列出需要目标播放器继续核实的项目。
不要把零错误写成整张谱保证可打。
~~~

## 提供哪些材料最有帮助

并非每次都要填全，技能会按任务利用现有信息：

- 新谱：具体音频或可用节拍标注、目标体验/难度范围、目标播放器及版本。
- 改谱：原始maidata、要修改的位置、音乐与动作意图、玩家反馈。
- 研究：源谱或确认视频、具体研究问题、可核实的作品与版本信息。
- 排错：发生问题的时间、原片段及前后文、工具警告、已有预览或手元。

只有曲名时可以做方案；没有听审条件时仍可研究实际取得的源谱与画面，但不能声称听准了歌。音频波形、节拍检测和机器转写都需要复核。

## 一次完整创作怎样进行

1. **建立时间坐标**：核对音源版本、first、BPM、变速、拍号、弱起与小节起点。
2. **规划整曲**：用段落表写清主声部、声音取舍、主体动作、相对负担以及前后衔接。
3. **先做骨架**：确认主要节奏、重音、长音与休止，再加入复杂配置。
4. **设计空间动作**：发展可识别的动机；为扫键、转圈和滑键复合安排入口与出口。
5. **复核连续任务**：把星头、等待、启动、移动、收尾及两手任务放在同一时间表。
6. **检查和迭代**：结构快检 → 完整解析/目标导入 → 动作与感应复核 → 视觉预览 → 有条件时试玩。
7. **交付与复盘**：说明修改理由和证据，记录未验证项，再依据反馈调整。

短问题或单点修改不会强制产出整套文档。休息、留白、高潮和技术爆发也不是必须依次出现的固定模板。

## 会交付哪些文件

按任务需要选择：

| 文件/内容 | 用途 |
|---|---|
| UTF-8 maidata.txt或原始simai片段 | 可编辑谱面草稿；目标播放器导入另验 |
| 段落规划表 | 记录音乐主线、选择与省略、动作和强度起伏 |
| 参考谱研究卡 | 记录来源、时间、观察事实、解释和迁移条件 |
| 分段审查表 | 记录两手占用、感应风险、修改及验证状态 |
| 最小修改补丁 | 便于核对原谱和修改后的差异 |
| 预览/检测记录 | 仅在对应工具确实运行时提供 |

模板在 [assets](assets/)；AI应根据实际任务填写，不能用空模板冒充研究结果。

## 自带的结构检查器

要求Python 3.9或更新版本，无第三方依赖。进入本技能目录：

~~~bash
python scripts/quick_lint.py assets/maidata-template.txt
python scripts/quick_lint.py path/to/maidata.txt
python -m unittest discover -s tests -v
~~~

检查器可以发现：

- 缺少谱面字段、空谱、重复字段、括号不匹配；
- 未找到独立结束E、E后仍有谱面内容；
- 首次输入前缺明确BPM或秒数网格，以及相对网格先于BPM；
- 已识别时值中的负数/零分母/零数量，区分可为零的显式等待；
- 部分可疑HOLD键位；未知时值和类似注释文本会提醒复核。

检查器**不会**验证完整音符语法、滑条几何、全部私有扩展、E是否覆盖所有长音尾部、音乐对轴、碰撞、真实手数或难度。未知符号与音符类型仍可能通过；不要用它替代成熟解析器。

退出码：0表示没有ERROR（仍可能有WARN）；1表示发现ERROR；2表示文件读取失败。零错误只代表没有触发已实现的规则。

## 怎么判断“检查到哪一步”

| 证据 | 能说明什么 | 不能代替什么 |
|---|---|---|
| 音乐与时间核对 | 实际核对的声部、拍点、偏移和落点 | 自动峰值不等于听审 |
| 结构快检 | 已实现的基础结构规则未触发或发现问题 | 完整语法、可玩性 |
| 完整解析/目标导入 | 对应工具及版本可以解析/导入 | 音乐表现、人体执行 |
| 连续动作与感应复核 | 对具体上下文的推演或模型风险 | 实测手顺与人体移动 |
| 视觉预览 | 对应画面下的时序、遮挡和读谱观察 | 真人手感 |
| 真人试玩 | 特定玩家和平台的实际反馈 | 所有玩家或所有版本 |

报告应注明工具版本、参数、位置与结果。没有做的保持“未验证”。官方谱例、赛事成绩、检测全绿和统计相似度，都不能直接认证新谱质量。

## 版本记录

### V2.0相对V1的变化

- 增加整曲结构、音乐取舍、休息/留白/高潮/技术爆发的方法和模板。
- 增加全曲参考与局部手法参考的研究流程，要求来源、时间和迁移条件。

- 扩展验证记录，区分音乐、解析、动作、画面和真人反馈。
- 修正示例E过早结束、零等待误报、负数时值漏报、初始时间参数和中间E漏检。
- 增加回归测试及两类技能行为试用请求；详见 [CHANGELOG](CHANGELOG.md)。

这些是方法与工具更新，不代表已经通过完整作品或真人测试取得官方谱师水平，也不承诺未经定义和评估的“官方质量百分比”。
